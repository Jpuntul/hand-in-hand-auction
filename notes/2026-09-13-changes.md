# 2026-09-13 — Remediation pass changelog

Grouped by concern. Workstream letters refer to `todo/`.

## Database / schema
- **Migrations squashed (S).** The 12 historical files are replaced by
  `20260913000000_baseline_{schema,functions,rls,ops}.sql`. Schema-neutral: local
  `db reset` old-chain vs new-baseline `pg_dump` diff was empty. Never edit the baseline files;
  add new migrations on top. Remote must be reset (`supabase db reset --linked`) once unpaused;
  the two dashboard Database Webhooks must be recreated (D6 moves them into a migration).
- **Bid log is now genuinely append-only and survives deletions (H, `20260913090100`–`090500`).**
  - `bid_history.user_id` / `item_id` FKs are `ON DELETE RESTRICT`: a user or item with bids
    can no longer be deleted (previously the cascade silently erased the bid log). Cancel the
    item instead; anonymise the user if ever needed (DB_AUDIT OQ-9).
  - Soft-cancel columns `cancelled_at`, `cancelled_by`, `cancel_reason` (reason required when
    cancelled); the admin `DELETE` policy on `bid_history` is gone. **Contract:** a "live" bid is
    `cancelled_at is null`; `items.bid_count` = count of live bids.
  - Canonical bid order is `id` (index `(item_id, id desc)` + partial live index);
    `created_at` now defaults to `clock_timestamp()` so it is monotonic per item.
  - `place_bid` v2: evaluates the window/anti-snipe with `clock_timestamp()` *after* taking the
    row lock, and **rejects bids above `greatest(min × 10, min + 10 000)`** (constants at the top
    of the function; confirm with organisers — DB_AUDIT OQ-2).
  - Cleanups: unused `notification_prefs_select_admin` policy dropped (it exposed push keys);
    duplicate indexes dropped; `bid_history` removed from the realtime publication (nothing
    subscribed; every bid was being broadcast to every client).
- **Auction lifecycle and admin overrides moved into SQL (B, `20260913110000`–`110500`).**
  - New `item_status` value **`paused`** (pause no longer overloads `scheduled`).
  - New `open_scheduled_auctions()`; cron job renamed to `auction-lifecycle` (every minute:
    open past-`start_time` scheduled items, close past-`end_time` open ones). Paused items are
    never auto-opened or auto-closed.
  - New `SECURITY DEFINER` RPCs `pause_item`, `resume_item`, `extend_deadline(minutes 1–1440)`,
    `force_close_item`, `cancel_last_bid(reason)` — each locks the `items` row, validates the
    transition, writes its own `audit_log` row in the same transaction. `cancel_last_bid`
    soft-cancels and recomputes `current_*`/`bid_count` from live bids, rolls back an anti-snipe
    extension, refreshes `winner_*` on closed items. `override-actions.ts` is now thin RPC calls
    (previously 3–4 non-atomic round trips that could desync `items` from `bid_history`).
  - **Function privileges:** `EXECUTE` revoked from `public`/`anon` on every function and via
    default privileges; only `server_time` (anon+auth), `place_bid`, `is_admin`, the five
    override RPCs (auth) are granted. `close_expired_auctions`/`open_scheduled_auctions` are
    cron-only. **Any new function needs an explicit `grant execute`.**
  - `log_audit` now requires a signed-in caller, an action matching `^(auth|admin)\.[a-z_.]+$`,
    resolves `actor_email` from `profiles` only, and is revoked from `anon`. Consequence: the
    unauthenticated failed-signup/sign-in audit calls in `lib/auth/actions.ts` no longer write —
    G decides whether to drop them or add `log_auth_failure`. Audit rows older than 90 days are
    pruned nightly (`audit-log-retention`).
  - `items` CHECKs: `bid_count >= 0`; `open ⇒ end_time not null`; `winner_* null unless
    closed`; `closed ⇒ winner_* = current_*`. **Consequence for admin UI:** moving a closed item
    to `cancelled` must null `winner_user_id`/`winning_bid` in the same statement; setting
    `open` requires an `end_time` (F handles the form side).
  - `deleteItem` refuses items with bids (DB also refuses via FK restrict).
- **`items` derived columns locked (H5, `20260913170000`).** `authenticated` can update only
  `item_no, name, description, sponsor, retail_value, starting_bid, bid_increment, start_time,
  end_time, status, image_urls, categories`. `current_bid`, `current_bidder_id`, `bid_count`,
  `winner_user_id`, `winning_bid` are written only by `place_bid`, the override RPCs and the
  cron functions (all `SECURITY DEFINER`). A `PATCH` on those columns → 42501.
  **Consequence:** a `closed` item cannot be moved to `cancelled` from the edit form any more
  (the winner CHECK needs `winner_*` nulled in the same statement); add a `cancel_item()` RPC
  if that path is needed (Z-deferred).
- **`profiles` column privileges (A5, `20260913100000`).** Bidders can update only
  `display_name`, `phone` (and `is_admin`, guarded by the `prevent_self_promotion` trigger).
  Table-level `UPDATE` was revoked from `authenticated`, then granted per column.
  **Gotcha for future columns on `profiles`:** a column-level `REVOKE` does nothing while a
  table-level `UPDATE` grant exists; with the table grant gone, any new column is *not*
  writable by bidders unless explicitly granted. Same pattern is required for `items` (H5).
  Also adds `CHECK` length limits: `display_name ≤ 100`, `phone ≤ 50`.

- **`items.notified_at timestamptz` (D3, `20260913130000`).** Set atomically by the
  `on-auction-closed` Edge Function (`update … where notified_at is null`) before any send, so
  closing an item twice (e.g. form save re-opens it, cron re-closes) notifies each person once.
- **Notification webhooks are now a migration (D6, `20260913130100`).** Function
  `install_notification_webhooks()` creates triggers `on_bid_placed_webhook`
  (`bid_history` insert) and `on_auction_closed_webhook` (`items` `update of status`, only when
  status changes) that POST to the Edge Functions with an `x-webhook-secret` header read from
  Supabase Vault (`webhook_secret`; optional `project_url`). **Setup:** run
  `select vault.create_secret('<value>', 'webhook_secret')` and
  `supabase secrets set WEBHOOK_SECRET=<same value>`, then re-run
  `select public.install_notification_webhooks()` whenever the secret changes. The dashboard
  webhooks are no longer needed. See `NOTIFICATIONS_SETUP.md`.

- **Donor PII locked down (C, `20260913120000`).** `profiles` SELECT is now own-row (+ admin);
  other users' names come from the new `public.public_profiles` view (`id, display_name` only,
  owner `postgres`, `security_invoker = false` on purpose). **API change:** any client query
  that embedded `profiles` for another user's name must embed `public_profiles` instead
  (`bidder:public_profiles!user_id(display_name)`); the item detail page already does.
  Bidder UUIDs on `items`/`bid_history` stay public by design — they resolve to display names
  only.
- Bid history reads now `order by id desc` (accepted order), not `created_at` (transaction
  start time; can invert under concurrent bids). Cancelled bids (`cancelled_at`, from H) are
  shown struck through and excluded from leader/trophy/bidder counts.

## Notifications / Edge Functions (D)
- Both Edge Functions now **refuse requests without the correct `x-webhook-secret`** (fail
  closed if the env var is unset) and re-read the row from the DB instead of trusting the
  webhook payload. Previously anyone with the public anon key could trigger won/lost emails.
- `on-auction-closed` fans out with a bounded pool (5) over one batched prefs query; winner
  first; also handles `open|paused → cancelled` with a new `cancelledEmail`.
- Push subscriptions are only accepted for known push-service hosts
  (Apple/FCM/Mozilla/WNS); other endpoints are rejected.
- `SUPABASE_SERVICE_ROLE_KEY` removed from `.env.example` and `DEPLOY.md` — the Next.js app
  never uses it. If it was ever added to Vercel, rotate it.

## Frontend / bidding UX (E)
- One server-corrected clock per page: `useNow()` (`src/hooks/use-now.ts`) provided via
  `NowContext` from `ItemsGrid`; `useServerTime` no longer returns a ref-reading getter (React
  Compiler safety). Cards flip to "Auction ended" the second `end_time` passes.
- `src/lib/auction.ts` is the single home for `minNextBid`, `isExpired`, `formatUsd`,
  `STATUS_VARIANT`.
- `ItemsGrid` takes `mode="auction" | "watchlist"`, drops closed/cancelled rows on realtime
  UPDATE, re-fetches after a websocket reconnect and shows a "Reconnecting…" pill.
- Item detail page is live: `live-item.tsx` subscribes to the item row; the bid dialog resets to
  the new minimum when the price moves and maps `place_bid` errors to friendly text.
- Item cards are real links (keyboard/middle-click work).

## Admin pages (F)
- Item edit is split: the generic form saves **details only** (`updateItem` sends just dirty
  fields; `status/start_time/end_time` are stripped server-side); a separate **Schedule** card
  calls `updateItemSchedule` which allows `scheduled | open | paused` only — `closed`/`cancelled`
  go through the override buttons. Datetime inputs keep seconds (`step="1"`). Zod runs on both
  client (`zodResolver`) and server. Saving the form can no longer clobber an anti-snipe
  extension or reopen an item cron just closed.
- `/admin/users` paginates (50/page) and reads bid counts from the `user_bid_counts` view (live
  bids only); dashboard revenue from `open_items_revenue` (`20260913140000`, both
  `security_invoker = true`). Previously counts were computed in JS over an unbounded fetch.
- `items-table.tsx` is a server component; rows are links.

## Security / authorization (A)
- Every admin server action now starts with `requireAdmin()` (`src/lib/auth/require-admin.ts`)
  and returns `{ ok:false, error:"Forbidden" }` for non-admins; mutations use `.select("id")`
  and treat zero rows as failure (previously RLS silently matched nothing and the action
  reported success + wrote an audit row).
- Item create/update/delete now write `admin.item.{create,update,delete}` audit rows.
- Open redirect closed: `safeRedirectPath()` (`src/lib/auth/redirect.ts`) on `/admin/login`.
- Profile updates validated server-side with `profileFieldsSchema` (`src/lib/auth/schemas.ts`),
  shared with signup.
